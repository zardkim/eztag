# 자동 태그 통합 개선 계획서

## 현황 분석

현재 자동 태그 기능은 **두 개의 분리된 흐름**으로 구현되어 있습니다.

| 구분 | 컴포넌트 | 진입점 | 방식 |
|------|----------|--------|------|
| 파일명 자동태그 | `FilenameAutoTagDialog.vue` | 자동태그 메뉴 → 파일 단위 | 파일명 패턴 파싱 → API 검색 → SSE 스트리밍 적용 |
| 폴더/앨범 검색 | `MetadataSearchModal.vue` | 자동태그 메뉴 → 폴더 단위 | 쿼리 직접 입력 → 앨범 목록 → 트랙 매칭 적용 |

**문제점:**
- 사용자가 목적에 맞는 메뉴를 스스로 구분해야 함
- UX 흐름이 단절되어 있어 재시도/전환 불가
- 검색 소스(Spotify 등) 선택이 각각 분리됨
- 결과 확인 후 다른 방식으로 재시도 불가

---

## 목표 구조

```
자동태그 버튼 클릭
    ↓
AutoTagDialog (통합 다이얼로그)
    ↓
Step 1: 방식 + 소스 선택
    ├─ [파일명으로 태그] 선택
    │       ↓
    │   Step 2A: 패턴 설정 + 파싱 미리보기
    │       ↓
    │   Step 3A: 실행 중 (SSE 진행 표시)
    │       ↓
    │   Step 4A: 결과 (파일별 상태 테이블)
    │
    └─ [앨범/폴더로 검색] 선택
            ↓
        Step 2B: 검색어 입력 + 앨범 검색 결과
            ↓
        Step 3B: 앨범 선택 → 트랙 목록 매칭 미리보기
            ↓
        Step 4B: 적용 결과 요약
```

---

## 상세 단계 설계

### Step 1 — 방식 선택 + 소스 선택 (통합)

**레이아웃:**
```
┌─────────────────────────────────────┐
│  🏷 자동 태그                        │
│  ① 방식·소스 > ② 설정 > ③ 실행 > ④ 결과 │
├─────────────────────────────────────┤
│  태그 방식을 선택하세요               │
│  ┌──────────────────┐ ┌───────────┐ │
│  │ 📄 파일명으로 태그 │ │ 💿 앨범 검색│ │
│  │ 파일명 패턴으로   │ │ 아티스트/앨범│ │
│  │ 트랙정보 자동 매칭│ │ 이름으로 검색│ │
│  └──────────────────┘ └───────────┘ │
│                                     │
│  검색 소스                           │
│  [Spotify ✓] [Melon] [Bugs]         │
└─────────────────────────────────────┘
```

- 방식과 소스를 한 화면에서 선택 (스텝 단축)
- 방식 카드는 선택 시 강조 표시, 단일 선택
- 소스는 활성화된 것만 표시, 복수 선택 가능

---

### Step 2A — 파일명 패턴 설정 (파일명 모드)

현재 `FilenameAutoTagDialog`의 Step 2와 동일하나 다음을 개선:

- 패턴 자동 감지 결과 → 신뢰도(%) + 감지된 패턴 표시
- 파싱 미리보기 테이블: **현재 태그 vs 파싱 결과** (변경될 값 파란색 강조)
- 패턴 프리셋 버튼 (멜론차트, 아티스트-제목 등)

---

### Step 2B — 앨범 검색 (앨범 모드)

현재 `MetadataSearchModal`을 개선·통합:

```
┌─────────────────────────────────────┐
│  검색어        [폴더명 자동 입력]    │
│  [아티스트 + 앨범명 ___________] 🔍 │
│                                     │
│  검색 결과                           │
│  ┌─────────────────────────────────┐│
│  │ 💿 앨범명          아티스트  연도││
│  │    트랙 12개                    ││
│  │ ─────────────────────────────  ││
│  │ 💿 앨범명2         아티스트  연도││
│  └─────────────────────────────────┘│
└─────────────────────────────────────┘
```

- 검색어를 현재 폴더명 기반으로 자동 채움
- 결과 클릭 시 Step 3B(트랙 매칭 미리보기)로 이동

---

### Step 3A — 실행 중 (파일명 모드)

현재와 동일: SSE 스트리밍 진행 표시 (프로그레스 바 + 현재 파일명)

---

### Step 3B — 트랙 매칭 미리보기 (앨범 모드)

**현재 MetadataSearchModal에 없는 신규 단계:**

```
┌─────────────────────────────────────────────────┐
│  💿 앨범명 · 아티스트 · 2024                     │
│  [← 다른 앨범 선택]                              │
│                                                  │
│  # │ Spotify 트랙          │ 로컬 파일       │상태│
│  1 │ 트랙 제목1            │ 01-트랙제목1.mp3│ ✅ │
│  2 │ 트랙 제목2            │ 02-트랙제목2.mp3│ ✅ │
│  3 │ 트랙 제목3            │ (매칭 없음)     │ ⚠️ │
│  - │ (Spotify에 없음)      │ 04-extra.mp3   │ — │
│                                                  │
│  ✅ 12개 매칭  ⚠️ 1개 불일치  — 1개 초과        │
└─────────────────────────────────────────────────┘
```

- 트랙 번호 기반 자동 매칭, 타이틀 퍼지 매칭 fallback
- 매칭 실패 트랙은 드롭다운으로 수동 선택 가능
- 커버아트 미리보기 포함

---

### Step 4A — 결과 (파일명 모드)

현재와 동일한 결과 테이블 + 다음 추가:

- 미매칭 파일에 대해 **"앨범 검색으로 재시도"** 버튼 (모드 전환)
- 되돌리기(Revert) 버튼

---

### Step 4B — 결과 (앨범 모드)

```
┌───────────────────────────────┐
│  ✅ 11개 적용    ⚠️ 1개 실패   │
│  💿 커버아트 적용됨            │
│                               │
│  파일명  │ 상태 │ 적용된 아티스트/제목 │
│  ...     │  ✅  │ ...              │
└───────────────────────────────┘
```

## 파일 변경 계획

### 신규 생성

| 파일 | 역할 |
|------|------|
| `frontend/src/components/AutoTagDialog.vue` | 통합 자동태그 다이얼로그 (메인) |

### 수정

| 파일 | 변경 내용 |
|------|-----------|
| `frontend/src/views/Browser.vue` | 자동태그 메뉴 버튼 → `AutoTagDialog` 단일 진입점으로 교체 |
| `frontend/src/i18n/ko.js` / `en.js` | 새 i18n 키 추가 |

### 삭제 (기능 통합 후)

| 파일 | 비고 |
|------|------|
| `frontend/src/components/FilenameAutoTagDialog.vue` | `AutoTagDialog`에 통합 |
| `frontend/src/components/MetadataSearchModal.vue` | 브라우저 뷰에서만 사용, `AutoTagDialog`에 통합 (라이브러리 뷰에서도 쓰인다면 유지 검토) |

> `MetadataSearchModal`은 라이브러리(Albums) 뷰에서도 사용 여부를 확인 후 삭제 또는 유지 결정

## 컴포넌트 내부 구조

```
AutoTagDialog.vue
├── props: { modelValue, files, availableProviders, folderName }
├── emit: ['update:modelValue', 'done']
│
├── state
│   ├── mode: 'filename' | 'album'
│   ├── step: 'select' | 'config' | 'preview' | 'running' | 'result'
│   ├── selectedProviders: string[]
│   │
│   ├── [filename mode]
│   │   ├── pattern: string
│   │   ├── previewRows: ParsedRow[]
│   │   ├── results: AutoTagResult[]
│   │   └── progress: { current, total, filename }
│   │
│   └── [album mode]
│       ├── searchQuery: string
│       ├── albumResults: AlbumResult[]
│       ├── selectedAlbum: AlbumResult | null
│       ├── matchPairs: MatchPair[]
│       └── applyResults: ApplyResult[]
│
└── sections (v-if mode + step)
    ├── StepSelect         (step='select')
    ├── StepFilenameConfig (mode='filename', step='config')
    ├── StepAlbumSearch    (mode='album',    step='config')
    ├── StepAlbumPreview   (mode='album',    step='preview')
    ├── StepRunning        (mode='filename', step='running')
    └── StepResult         (step='result')
```

## 백엔드 변경 사항

기존 API를 그대로 사용하므로 **백엔드 변경 없음.**

| API | 용도 |
|-----|------|
| `POST /browse/detect-filename-pattern` | 패턴 자동 감지 |
| `POST /browse/tag-from-name/preview` | 파싱 미리보기 |
| `POST /metadata/auto-tag-by-filename` (SSE) | 파일명 모드 실행 |
| `GET /metadata/search` | 앨범/트랙 검색 |
| `GET /metadata/album-tracks` | 앨범 트랙 목록 |
| `POST /metadata/apply-by-path` | 트랙 태그 적용 (경로 기반) |
| `POST /metadata/apply-album-cover` | 커버아트 적용 |
| `POST /metadata/revert-auto-tag` | 되돌리기 |

## 단계별 진행 표시 (헤더 브레드크럼)

| 모드 | 진행 단계 |
|------|-----------|
| 파일명 | ① 방식·소스 › ② 패턴 설정 › ③ 실행 중 › ④ 결과 |
| 앨범 검색 | ① 방식·소스 › ② 앨범 검색 › ③ 트랙 매칭 › ④ 결과 |

## 구현 순서

1. `AutoTagDialog.vue` 신규 생성 — Step 1(방식+소스 선택) 구현
2. 파일명 모드 Step 2A → 3A → 4A 구현 (기존 `FilenameAutoTagDialog` 코드 이식)
3. 앨범 모드 Step 2B(검색) → 3B(트랙 매칭 미리보기) → 4B 구현 (기존 `MetadataSearchModal` 코드 이식 + 미리보기 신규)
4. `Browser.vue` 자동태그 메뉴 → `AutoTagDialog` 단일 진입으로 교체
5. 기존 두 컴포넌트 제거
