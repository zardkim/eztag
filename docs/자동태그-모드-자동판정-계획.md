# 자동태그 모드 자동 판정 계획

> 앨범 단위 / 파일명 단위를 사용자가 버튼으로 고르지 않고 자동으로 정한다.
>
> 작성일: 2026-09-06 · 기준 버전 v0.10.1(+미푸시 커밋)

---

## 1. 지금 구조와 요청의 범위

| 모드 | 흐름 |
|---|---|
| 앨범 단위 | `select`(모드·소스 선택) → `alb_search`(검색어 자동 구성 + 자동 검색 → **사용자가 앨범 선택**) → `alb_compare`(공통 태그 확인) → 적용 → `alb_result` |
| 파일명 단위 | `select` → `fn_config`(패턴 자동 감지 + 옵션) → `fn_running` → `fn_result` |

**중요.** 앨범 모드는 이미 검색어를 기존 태그에서 자동 구성하고 자동 검색까지 합니다.
사람이 개입하는 지점은 **검색 결과 중 어느 앨범인지 고르는 것**입니다.

따라서 이 계획으로 없어지는 것은 **모드 선택 클릭 하나**이고,
앨범 모드의 앨범 선택 단계는 그대로 남습니다. 그것까지 자동화하는 건 성격이 다른
별개 문제라 §7에 선택 과제로 분리했습니다.

두 모드 모두 **되돌리기(revert)가 이미 있습니다** — 오판정의 최후 안전망입니다.

---

## 2. 설계의 축 — 오판정 비용이 비대칭이다

| 오판정 | 결과 |
|---|---|
| 컴필레이션인데 **앨범 모드** | 서로 다른 100곡에 **한 앨범의 공통 태그를 덮어씀**. 앨범명·앨범아티스트·연도·장르가 전부 틀림 |
| 단일 앨범인데 **파일명 모드** | 트랙마다 개별 검색 → 대개 **같은 앨범을 찾아 올바르게** 태깅됨. 느리고 커버가 폴더에 안 써질 뿐 |

한쪽만 크게 나쁩니다. 그러므로:

> **기본은 파일명 단위. 앨범 단위는 "이 폴더는 한 장의 앨범이다"라는 적극적 근거가 있을 때만.**

---

## 3. 판정에 쓸 데이터 — 추가 요청이 0이다

다이얼로그를 열 때 `browserStore.files` 에 이미 전체 태그가 들어 있습니다
(`/browse/files` 가 `album_title`, `album_artist`, `artist`, `year`, `track_no` … 를 반환).
**새 API 호출 없이 즉시 판정할 수 있습니다.**

### 3.1 실제 폴더 측정 (2026-09-06)

| 폴더 | N | 앨범수 | 아티스트수 | album_artist | 실제 성격 |
|---|---|---|---|---|---|
| 멜론 Top100 | 100 | **89** | 66 | 65종 | 차트(컴필) |
| 가을동화 OST | 2 | 2 | 1 | (없음) | OST |
| Apink - It Girl | 2 | **1** | 1 | `Apink (에이핑크)` | 단일 앨범 |
| 차안에서 들으면 좋은 R&B POP | 46 | **1** | **24** | `Various Artists` | 컴필 |

**마지막 줄이 설계를 바로잡았습니다.** 앨범명이 1개인데도 컴필레이션입니다
(플레이리스트 이름이 앨범 태그에 들어간 경우). 즉 **앨범명 개수만으로는 판정할 수 없습니다.**

동시에, 처음 우려했던 "Top100 이 앨범명 1개로 뭉쳐 있어 앨범으로 오판될 것"은
실제로는 일어나지 않았습니다(89개). 우려의 방향이 반대였습니다.

### 3.2 신호별 판별력

| 신호 | 판별력 | 비고 |
|---|---|---|
| `album_title` 고유 개수 | 높음 (단, 단독으로는 불충분 — 위 4번째 사례) | |
| `album_artist` 고유 개수 + V.A. 여부 | **가장 높음** | 피처링이 섞여 `artist` 가 흩어져도 `album_artist` 는 유지됨 |
| `artist` 고유 개수 | 보조 | `album_artist` 가 비어 있을 때 대체 |
| 태그 보유율 | 전제 조건 | 태그가 없으면 어떤 신호도 못 씀 → 파일명 모드 |
| 파일 수 | 쓰지 않음 | 46곡 컴필 · 2곡 앨범이 모두 있어 변별력 없음 |
| 폴더명 키워드 | **쓰지 않음** | "Top100/모음/Best" 매칭은 언어·표기에 취약하고 틀렸을 때 조용히 망가짐 |

## 4. 판정 규칙

```
V.A. 표기 = { "various artists", "various", "v.a.", "va", "여러 아티스트", "모음" }

taggedRatio        = album_title 있는 파일 / 전체
distinctAlbums     = album_title 고유 개수
distinctAlbumArtists = album_artist 고유 개수
distinctArtists    = artist 고유 개수

앨범 단위로 판정 (아래를 모두 만족):
  1. taggedRatio >= 0.8            — 판단 근거가 될 태그가 있어야 함
  2. distinctAlbums == 1           — 한 앨범을 가리켜야 함
  3. album_artist 가 V.A. 표기가 아님
  4. distinctAlbumArtists == 1     (album_artist 가 비어 있으면 distinctArtists <= 3 으로 대체)

그 외 전부 → 파일명 단위
```

### 4.1 측정 폴더에 적용

| 폴더 | 판정 | 근거 |
|---|---|---|
| 멜론 Top100 | 파일명 | 앨범 89개 |
| 가을동화 OST | 파일명 | 앨범 2개 |
| Apink - It Girl | **앨범** | 앨범 1 · album_artist 1(V.A. 아님) |
| R&B POP | 파일명 | 앨범은 1이나 album_artist 가 `Various Artists` |

4개 모두 사람의 판단과 일치합니다.

### 4.2 `album_artist` 를 `artist` 보다 앞세우는 이유

피처링이 많은 정규 앨범은 `artist` 가 열 갈래로 흩어져도 `album_artist` 는 하나로 유지됩니다.
`artist` 개수만 보면 그런 앨범을 컴필로 오판합니다. `album_artist` 가 비어 있을 때만
`artist` 를 보조로 씁니다.

## 5. 사용자에게 보이는 것

"선택 없이 자동"은 **필수 클릭이 없다**는 뜻이지, 결정이 안 보인다는 뜻이 아닙니다.
자동 판정이 틀렸을 때 한 번의 동작으로 빠져나갈 수 있어야 합니다.

다이얼로그를 열면 판정된 모드의 설정 화면으로 **바로 진입**하고, 상단에 근거 배너를 둡니다.

```
┌────────────────────────────────────────────────────────────┐
│ ✦ 자동 판정: 파일명 단위                                    │
│   앨범 89개 · 아티스트 66명 — 트랙마다 앨범이 다릅니다      │
│                                    [앨범 단위로 바꾸기]     │
└────────────────────────────────────────────────────────────┘
```

- 근거는 **판정에 실제로 쓴 수치**를 그대로 보여줍니다(문구만 다른 게 아니라 검증 가능해야 함)
- 반대 모드로 가는 버튼 하나를 항상 둡니다
- 수동으로 바꾸면 그 선택을 기억합니다(현재 `eztag-autotag-mode` localStorage 재사용).
  **단, 폴더가 바뀌면 다시 자동 판정**합니다 — 기억이 자동 판정을 영구히 이기면 안 됩니다

### 5.1 근거가 부족할 때

`taggedRatio < 0.8` (거의 태그가 없는 폴더)이면 판정할 근거가 없습니다.
이때도 파일명 단위로 진행하되 배너 문구를 다르게 합니다:

```
✦ 자동 판정: 파일명 단위
  기존 태그가 거의 없어 폴더 성격을 알 수 없습니다. 트랙마다 개별 검색합니다.
```

> 합니다. 이 프로젝트에는 테스트가 없으므로, 최소한 함수 하나로 격리해 두면
> 실제 폴더 태그를 넣어 결과를 재현할 수 있습니다.

## 7. 결정이 필요한 항목

1. **`select` 단계를 완전히 없앨 것인가.** 지금은 모드 + provider 를 함께 고릅니다.
   모드가 자동이 되면 provider 선택만 남는데, provider 도 마지막 선택을 기억하므로
   **첫 실행 이후에는 단계 자체를 건너뛸 수 있습니다.**
   권장: 저장된 provider 가 있으면 `select` 를 건너뛰고 바로 설정 화면으로.

2. **앨범 모드의 앨범 선택까지 자동화할 것인가** (§1 에서 분리한 문제).
   검색 결과 1위를 자동 선택하고 `alb_compare` 에서 확인만 받는 방식이 가능합니다.
   다만 앨범 모드는 **폴더 전체에 공통 태그를 덮어쓰므로** 오선택 비용이 파일명 모드보다
   훨씬 큽니다. 권장: **이번에는 하지 않음.** 모드 자동 판정을 먼저 써보고 판단.

3. **임계값** — `taggedRatio 0.8`, `distinctArtists <= 3` 은 §3.1 측정에서 뽑았지만
   표본이 4개 폴더입니다. 실제 라이브러리에서 오판정이 나오면 조정이 필요합니다.
   `decideMode` 를 순수 함수로 두는 것이 이 조정을 쉽게 만듭니다.

## 8. 하지 않기로 한 것

- **폴더명 키워드 판정** ("Top100", "모음", "Best" …) — 언어·표기에 취약하고, 틀렸을 때
  근거가 사용자에게 보이지 않아 조용히 망가집니다. 태그 통계는 배너에 숫자로 보여줄 수 있습니다.
- **파일 수 기준** — 46곡 컴필과 2곡 앨범이 실제로 존재해 변별력이 없습니다(§3.2).
- **자동 판정 후 곧바로 실행** — 판정만 자동이고 실행은 사용자가 누릅니다.
  두 모드 모두 파일을 되돌릴 수 있지만, 확인 없이 100곡을 건드리는 건 다른 문제입니다.
