# 사이드바 폴더 트리 전환 계획

> 좌측 사이드바를 「작업공간 / 라이브러리」 점선 버튼 + 팝업 피커 방식에서,
> Claude Design `eztag Workbench` 디자인의 **트리 뷰**로 전환한다.
>
> - 작성일: 2026-09-01
> - 기준 버전: v0.9.8
> - 디자인 원본: `claude.ai/design/p/62de710d-0a93-4352-bc6b-5f790d91cb51` → `eztag Workbench.html`

---

## 1. 목표

라이브러리 폴더와 작업공간 폴더를 **하나의 좌측 트리**에 섹션으로 나눠 표시하고,
펼침/접기로 하위 폴더를 탐색한다. 현재의 팝업 피커(`LibraryPickerModal`) 왕복을 없앤다.

**비목표(이번 범위 밖)**
- Workbench 3-Col 레이아웃(가운데 시트 + 우측 인스펙터) 전면 도입
- Smart groups(Missing art / No year / Duplicates …) — eztag에 해당 개념 자체가 없음
- 모바일 레이아웃 변경 — 사이드바 `<aside>`는 `App.vue:119`에서 `hidden lg:flex`이므로 데스크톱 전용(lg 이상)이다. 모바일은 기존 하단 탭 + 폴더 그리드를 그대로 유지한다

## 3. 현재 코드 현황

### 3.1 가장 중요한 사실 — 트리 컴포넌트가 이미 있고, 안 쓰이고 있다

| 컴포넌트 | 상태 |
|---|---|
| `frontend/src/components/FolderTree.vue` (115줄) | **완성돼 있으나 어디서도 import되지 않음** |
| `frontend/src/components/FolderNode.vue` (130줄) | 재귀 렌더링·지연 로딩·sessionStorage 캐시(TTL 5분) 구현 완료, 미사용 |
| `frontend/src/components/WorkspaceSidebar.vue` | `App.vue:173`이 실제로 마운트하는 사이드바. **트리가 아님** |

현재 `WorkspaceSidebar.vue`의 구조:

```
🏠 홈
[📂 작업공간] [📚 라이브러리]   ← 점선 버튼 2개 → LibraryPickerModal 팝업
─────────────
현재 폴더 카드 (영역별 주황/노랑 배경 + ✎ 이름변경)
─────────────
파일 목록 (오디오 + LRC/이미지/HTML)
```

즉 이번 작업은 **트리 신규 개발이 아니라, 있는 트리를 이중 영역으로 확장해 사이드바에 심는 일**이다.

### 3.2 백엔드 — 자식 로딩은 이미 양쪽 영역을 지원한다

`browse.py:186`:

```python
p = _validate_path(path, db, allow_workspace=True)
```

`_validate_path`(`browse.py:66`)는 `allow_workspace=True`일 때 허용 루트에
`get_workspace_path(db)`를 추가하고, 기본으로 `ScanFolder` 전체 + `get_library_path(db)`를 포함한다.
이는 `workspace.py`의 `workspace_roots` / `library_roots`가 반환하는 루트 집합과 정확히 일치한다.

→ **`GET /api/browse/children`은 이미 작업공간·라이브러리 경로를 모두 처리한다.**
게다가 `_quick_scan` 조기 종료 최적화(커밋 `0d98104`)와 서버 캐시가 적용돼 있고,
응답이 `FolderNode`가 그대로 소비하는 `[{ name, path, has_children, has_audio }]` 형태다.

경로 정규화도 확인했다. `_validate_path`는 `roots.append(get_workspace_path(db))`를 `.resolve()` 없이 호출하지만,
`get_workspace_path`/`get_library_path`가 **내부에서 이미 `.resolve()`한 `Path`를 반환**한다(`config_store.py:128`, `:145`).
기본값이 상대경로 `"../data/workspace"`여도 비교는 절대경로끼리 이뤄진다.

**자식 로딩 관련 백엔드 신규 개발은 0이다.**

> ✅ **2026-09-01 실측 완료 (Task 0).** 로컬 백엔드를 띄우고 실제 호출로 확인했다.
>
> | 호출 | 결과 |
> |---|---|
> | `/browse/children` — 작업공간 루트 | **200**, `[{name, path, has_children, has_audio}]` |
> | `/browse/children` — 라이브러리 루트 | **200**, 동일 형태 |
> | `/browse/children` — 라이브러리 2단계 하위 | **200**, 동일 형태 |
> | `/workspace/workspace/roots` | **200** `{roots:[…], configured:true}` |
> | `/workspace/library/roots` | **200** `{roots:[…]}` |
>
> 응답 형태가 `FolderNode`가 그대로 소비하는 모양임을 확인했다. §3.2는 추론이 아니라 **검증된 사실**이다.
> 단 심볼릭 링크 루트는 별개 문제로 드러났다 — §3.5 참조.

### 3.3 백엔드 — 진짜 공백은 「루트 목록」 하나

`GET /api/browse/roots`는 `ScanFolder` 테이블만 읽는다. 그런데 `main.py` lifespan은
**라이브러리 경로만** `ScanFolder`로 등록하고 작업공간은 등록하지 않는다.
따라서 `/browse/roots`만으로는 작업공간 루트를 얻을 수 없다.

| 방안 | 내용 | 평가 |
|---|---|---|
| **A. 프론트 병합** | `workspaceApi.workspaceRoots()` + `libraryRoots()` 두 호출을 프론트에서 합치고 area 태그 부착 | **채택** — 백엔드 변경 0, 두 API 모두 이미 존재 |
| B. 집계 엔드포인트 | `/api/browse/roots?area=all` 신설 | 왕복 1회로 줄지만 신규 코드 + 마이그레이션 부담 |

두 루트 API는 응답 형태가 다르므로(`{roots, configured}` vs `{roots}`) 프론트에서 정규화한다.

### 3.4 성능 주의 — 트리는 느린 엔드포인트를 피해 간다

`workspace.py`의 `workspace_children`(:812)과 `library_children`(:895)은
자식 폴더마다 `item.rglob("*")`로 **전체 재귀 탐색**을 돌려 `has_audio`를 구한다.
`0d98104`가 `browse.py`에서 걷어낸 바로 그 N+1 패턴이 여기엔 남아 있다.

트리가 `/browse/children`을 쓰므로 이 문제를 **우회**한다.
두 엔드포인트는 `LibraryPickerModal`(이동 대상 선택 등)에 계속 쓰이므로 그대로 둔다.
별도 개선 과제로 분리한다.

### 3.5 심볼릭 링크 루트 — ✅ **해결 2026-09-01**

Task 0에서 심볼릭 링크를 만들어 테스트한 결과, **트리와 무관하게 v0.9.8에서 이미 깨져 있었다.**

| 호출 | 수정 전 | 수정 후 |
|---|---|---|
| `/browse/children` — 링크 부모 폴더 | 200이지만 **링크가 목록에 없음** | 200, 링크 표시됨 |
| `/browse/children` — 링크 경로 직접 | **403** | **200** |
| `/workspace/library/children` — 링크 경로 | **403** | **200** |
| 링크 하위 폴더 rename | **403** | **200** |

원인은 `Path(path).resolve()`가 링크를 끝까지 따라가, 링크 대상(`/volume1/music/...`)이
등록된 어떤 루트 아래에도 없게 되는 것이었다. 같은 패턴이 검증 함수 3개와 인라인 검사 ~10곳에 복제돼 있었다.

**수정 방식** — `backend/app/core/path_guard.py` 신설, 모든 경로 검사를 여기로 통일:

- `safe_path(raw)` — 절대경로가 아니거나 `..`가 하나라도 있으면 거부한 뒤 `os.path.normpath`로만 정리.
  **심볼릭 링크는 따라가지 않는다.** `..` 거부가 어휘적 비교를 안전하게 만드는 핵심 조건이다
  (`..`를 허용하면 `/music/link/../passwd`가 `/music/passwd`로 정규화돼 통과하지만
  커널은 링크를 따라간 뒤 `..`를 적용해 루트 밖 파일을 연다).
- `is_within(p, root)` — 어휘적 비교를 먼저(루트 **안의** 링크 허용), 실패 시 양쪽 resolve 후 재비교
  (루트 **자체가** 링크인 경우 보존).
- 검증 함수는 **어휘적 경로를 반환**한다. resolve한 경로를 돌려주면 이후 `scandir`가 링크 대상 접두사로
  자식 경로를 만들어 다음 요청이 다시 403이 된다.
- `browse.py`의 `is_dir(follow_symlinks=False)` 4곳을 완화해 링크 폴더가 목록에 나오게 했다.

**아직 남은 것 (별도 과제)** — 재귀 보기는 심볼릭 링크를 통과하지 못한다.
`os.walk`(browse.py:2419, 2444)는 `followlinks=False`가 기본이고 `rglob`(workspace.py:813, 893)도 링크를 따라가지 않는다.
켜려면 무한 루프 방지를 위한 방문 inode 집합이 필요해 별도 변경으로 분리한다.

## 5. 적용 설계

### 5.1 데이터 계층

`FolderTree.vue`에 루트 로더를 신설한다.

```js
async function loadRoots(force = false) {
  const [ws, lib] = await Promise.all([
    workspaceApi.workspaceRoots(),   // { roots:[{name,path,has_children}], configured }
    workspaceApi.libraryRoots(),     // { roots:[...] }
  ])
  sections.value = [
    { key: 'workspace', labelKey: 'sidebar.workspaceSection',
      nodes: ws.data.roots.map(r => ({ ...r, area: 'workspace', isRoot: true })) },
    { key: 'library',   labelKey: 'sidebar.librarySection',
      nodes: lib.data.roots.map(r => ({ ...r, area: 'library',   isRoot: true })) },
  ]
}
```

`workspace_roots`가 `configured: false`이거나 `roots`가 비면 **해당 섹션 헤더까지 통째로 숨긴다**
(빈 헤더만 남기지 않는다). 라이브러리도 동일.

자식은 기존대로 `browseApi.getChildren(path, force)` — 영역 구분 없이 공통.

### 5.2 메워야 할 구멍 4개

**① area 전파 (가장 중요)**

`FolderTree.vue:37`의 현재 코드는 area 없이 호출한다:

```js
browserStore.selectFolder(folder)          // ← area 누락
```

`selectFolder(folder, crumb = null, area = null)`는 `if (area) currentArea.value = area`이므로,
area를 안 넘기면 `currentArea`가 **이전 값 그대로 남는다**. 작업공간 노드를 눌렀는데
라이브러리 상태가 유지되면 영역별 색상·현재폴더 카드·「라이브러리로 이동」 로직이 어긋난다.

→ 루트 노드에 부여한 `area`를 **자식으로 내려보내고, select 이벤트에 실어 올려보낸다.**
`FolderNode`에 `area` prop을 추가하고 자식 렌더링 시 그대로 전달, `loadChildren` 결과에도 주입한다.

**② breadcrumb 조상 체인**

`selectFolder`의 `crumb === null` 분기는 *"현재 breadcrumb에 이어붙이거나 잘라낸다"* 로 동작한다
(`browser.js:339~348`). 트리는 임의 위치로 점프할 수 있으므로 이 폴백은 **엉뚱한 경로를 누적**한다.

→ 각 `FolderNode`가 `ancestors` prop(루트→부모 체인)을 들고, select 시
`[...ancestors, { name, path }]`를 crumb으로 함께 emit한다.

**③ 단일 루트 평탄화 꼼수 제거**

`FolderTree.vue:60`:

```js
const result = data.length === 1 && data[0].children?.length > 0 ? data[0].children : data
```

루트 집합이 둘이 되면 의미가 깨진다. 삭제한다.

**④ 캐시 키 스코프**

`sessionCache` 키 `'roots'`는 영역 구분이 없다 → `roots:workspace` / `roots:library`로 분리.
`children:${path}`는 절대경로 기반이라 그대로 둔다.

### 5.3 `WorkspaceSidebar.vue` 재구성

| 구역 | 조치 |

## 10. 후속 작업 — 폴더 로딩 성능

2026-09-01 실측 결과를 근거로 정리한 개선 과제. **2·3번은 완료**, 1번이 남아 있다.

### 10.1 [남음 · 우선순위 최상] `_quick_scan` N+1 제거

**현상.** `GET /api/browse/children` 은 부모 폴더 1회 + **자식 폴더마다 `_quick_scan` 1회**를 돈다.
용도는 캐럿(`has_children`)과 `♪`(`has_audio`) 표시뿐이다.

```
하위 폴더 5,000개 → scandir 5,001회
로컬 SSD          :   82 ms   ← 문제 없음
NAS  5 ms/call    :   25 초
NAS 10 ms/call    :   50 초
NAS 20 ms/call    :  100 초
```

커밋 `0d98104` 이 조기 종료(`break`)로 **1회당 비용**은 이미 줄였지만 **호출 횟수 N** 은 그대로다.
SMB/NFS 왕복 지연이 붙는 순간 이 항목이 전체를 지배한다.

**개선 방향 (택1 또는 병행)**

- (a) **메타 지연** — 응답에서 `has_children`/`has_audio` 를 빼고 캐럿은 일단 항상 표시.
  펼쳤을 때 자식이 없으면 캐럿을 제거한다 (VS Code 탐색기 방식). scandir 5,001회 → **1회**
- (b) **점진적 보강** — `?meta=false` 로 빠른 목록을 먼저 주고, `♪` 는 별도 요청으로 나중에 채운다

**주의.** API 응답 형태가 바뀌므로 `FolderNode` 의 캐럿 표시 조건
(`node.has_children || node.isRoot`)과 `♪` 렌더링을 함께 수정해야 한다.
착수 전 실제 NAS 라이브러리에서 하위 폴더가 가장 많은 디렉터리로 체감 시간을 측정할 것.

### 10.2 [완료 2026-09-01] 프론트 sessionStorage 캐시가 조용히 죽던 문제

sessionStorage 실측 한도는 **약 4.9MB**. 하위 폴더 5,000개 응답이 709KB 이므로 **7개면 가득** 찼다.
`cache.js` 의 `set()` 이 `QuotaExceededError` 를 `catch {}` 로 삼키고 축출 정책이 없어서,
한 번 가득 차면 **그 세션 내내 캐시가 전혀 동작하지 않았다** — 작은 폴더까지, 에러도 없이.

→ `MAX_ENTRY_BYTES`(256KB) 초과 항목은 저장하지 않고, 용량 초과 시 `ts` 기준 오래된 항목부터
지우고 재시도하도록 수정.

### 10.3 [완료 2026-09-01] 백엔드 캐시 상한이 개수 기준이라 메모리 폭발 가능

`maxsize` 가 **항목 수**여서 항목 크기와 무관했다. 최악의 경우:

| 캐시 | 항목당 | 최악 |
|---|---|---|
| `_files_cache` 500개 | 2.6MB (파일 1,000개 폴더) | **1.3GB** |
| `_cover_data_cache` 500개 | 커버 원본 바이너리 | 수백 MB ~ GB |
| `_children_cache` 500개 | 709KB (폴더 5,000개) | 346MB |

Synology DS220j 는 RAM 이 512MB 다.

→ `getsizeof` 로 **바이트 상한** 전환. 총 예산은 `CACHE_MEMORY_MB` 환경변수(기본 128MB)로 조절.
단일 항목이 상한을 넘으면 예외 없이 캐싱만 생략한다. `cache.stats()` 로 사용량 진단 가능.
