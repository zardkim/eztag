# 특수문자 및 한자 처리 방법

## 1. 현황 분석

### 1.1 문제가 발생하는 구간

| 구간 | 위치 | 현재 상태 |
|------|------|-----------|
| 태그 저장 | `tag_writer.py` | UTF-8(encoding=3) 사용 → 대부분 정상 |
| 파일명 변경 | `pattern_rename.py` | `\/:*?"<>|` → `_` 치환 구현됨 |
| 자동태그 파일명 파싱 | `filename_parser.py` | 특수문자 포함 파일명 파싱 미흡 |
| 메타데이터 API 검색 | `metadata/matcher.py` | 쿼리 문자열 정규화 미구현 |
| 프론트엔드 입력 | TagPanel, BatchTagPanel | 특수문자 입력 허용되나 검증 없음 |

## 2. 특수문자 분류

### 2.1 파일명 금지 문자 (OS별)

| 문자 | 설명 | Windows | Linux/Mac | 현재 처리 |
|------|------|---------|-----------|-----------|
| `\` | 백슬래시 | 금지 | 허용 | `_` 치환 ✅ |
| `/` | 슬래시 | 금지 | 금지(경로 구분자) | `_` 치환 ✅ |
| `:` | 콜론 | 금지 | 허용 | `_` 치환 ✅ |
| `*` | 별표 | 금지 | 허용 | `_` 치환 ✅ |
| `?` | 물음표 | 금지 | 허용 | `_` 치환 ✅ |
| `"` | 큰따옴표 | 금지 | 허용 | `_` 치환 ✅ |
| `<` | 꺽쇠 열기 | 금지 | 허용 | `_` 치환 ✅ |
| `>` | 꺽쇠 닫기 | 금지 | 허용 | `_` 치환 ✅ |
| `\|` | 파이프 | 금지 | 허용 | `_` 치환 ✅ |

> **현재 `pattern_rename.py`의 `sanitize_filename()`에서 위 문자는 이미 처리 중.**

### 2.2 태그 값에 허용되나 주의가 필요한 문자

| 문자 | 예시 | 태그 저장 | 파일명 변환 시 | 비고 |
|------|------|-----------|----------------|------|
| `?` | `What's Up?` | 허용 ✅ | `_` 치환 필요 | 검색 쿼리에서도 제거 필요 |
| `/` | `AC/DC` | 허용 ✅ | `_` 치환 필요 | 아티스트명에 빈번 |
| `:` | `Part 1: Intro` | 허용 ✅ | `_` 치환 필요 | 앨범/곡명에 빈번 |
| `"` | `"Heroes"` | 허용 ✅ | `_` 치환 필요 | David Bowie 곡명 등 |
| `...` / `…` | `Wait...` | 허용 ✅ | 허용 | 말줄임표 |
| `'` `'` | 곡명 따옴표 | 허용 ✅ | 허용 | 유니코드 따옴표 |

### 2.3 전각(Fullwidth) 특수문자 (CJK 텍스트에 빈번)

| 전각 문자 | 대응 ASCII | 유니코드 | 처리 방향 |
|-----------|-----------|---------|-----------|
| `：` | `:` | U+FF1A | 태그 값: 보존 / 파일명: `_` 치환 |
| `？` | `?` | U+FF1F | 태그 값: 보존 / 파일명: `_` 치환 |
| `！` | `!` | U+FF01 | 태그 값: 보존 / 파일명: 허용 |
| `／` | `/` | U+FF0F | 태그 값: 보존 / 파일명: `_` 치환 |
| `＊` | `*` | U+FF0A | 태그 값: 보존 / 파일명: `_` 치환 |
| `＼` | `\` | U+FF3C | 태그 값: 보존 / 파일명: `_` 치환 |
| `＜＞` | `<>` | U+FF1C/FF1E | 태그 값: 보존 / 파일명: `_` 치환 |

> **현재 `sanitize_filename()`은 전각 특수문자를 처리하지 않음 → 개선 필요**

### 2.4 한자(漢字/CJK) 처리

한자는 Unicode CJK Unified Ideographs (U+4E00–U+9FFF, U+3400–U+4DBF 등)에 속한다.

| 항목 | 현재 상태 | 문제점 |
|------|-----------|--------|
| 태그 저장 | UTF-8로 정상 저장 ✅ | 없음 |
| 파일명 사용 | Linux/Mac에서 정상 ✅ | macOS NFD 정규화 이슈 |
| 파일명 파싱 | 패턴 매칭 정상 | 한자가 구분자(`-`, 공백)와 혼재 시 오파싱 가능성 |
| 메타데이터 검색 | 대체로 정상 | 일부 API에서 한자 쿼리 결과 부정확 |

## 3. 발생 가능한 문제 시나리오

### 시나리오 A: 자동태그 — 파일명 파싱 오류
```
파일명: 01 - What's Up？ (feat. 张杰).mp3
패턴:   %track% - %title%
문제:   `？`(전각)가 패턴 구분자와 혼재되어 파싱 오류
```

### 시나리오 B: 파일명 변경 — 전각 특수문자 미처리
```
태그 title: "Dragon：Reborn／上"
패턴: %title%
결과: "Dragon：Reborn／上.mp3"  ← 전각 :, / 가 Linux에선 허용이나 Windows에서 오류
기대: "Dragon_Reborn_上.mp3"
```

### 시나리오 C: 메타데이터 검색 쿼리의 특수문자
```
파일명: AC∕DC - Highway to Hell.mp3  (∕ = U+2215 Division Slash)
검색 쿼리: "AC∕DC Highway to Hell"
문제:  일부 API에서 ∕를 토큰 구분자로 인식해 검색 실패
```

### 시나리오 D: 태그 입력 — 파일명 변환 시 미처리
```
태그 편집에서 artist에 "AC/DC" 입력 후 파일명 변경
패턴: %artist% - %title%
결과: "AC/DC - Song.mp3"  ← /가 경로 구분자로 해석되어 오류
기대: "AC_DC - Song.mp3"
```

## 4. 개선 계획

### 4.1 `pattern_rename.py` — `sanitize_filename()` 개선

**현재:**
```python
INVALID_CHARS = re.compile(r'[\\/:*?"<>|]')
```

**개선안:**
```python
INVALID_CHARS = re.compile(
    r'[\\/:*?"<>|'
    r'\uff0a\uff0f\uff1a\uff1c\uff1e\uff1f\uff3c'  # 전각 특수문자
    r'\u2215\u2216'  # Division Slash, Set Minus
    r']'
)
```

추가 처리:
- 전각 문자 → ASCII 대응 또는 `_` 치환
- Unicode 정규화: `unicodedata.normalize('NFC', name)` 적용 (macOS NFD 대응)
- 255바이트 제한: 이미 구현됨 (UTF-8 멀티바이트 고려 필요 확인)

### 4.2 `metadata/matcher.py` — 검색 쿼리 정규화

메타데이터 검색 전 쿼리 문자열 전처리 함수 추가:

```python
import re
import unicodedata

def normalize_search_query(text: str) -> str:
    """API 검색 쿼리용 문자열 정규화."""
    if not text:
        return text
    # NFC 정규화
    text = unicodedata.normalize('NFC', text)
    # 전각 → 반각 변환 (알파벳/숫자/기호)
    text = text.translate(_FULLWIDTH_TABLE)
    # 검색에 방해되는 특수문자 제거 (따옴표, 괄호 등)
    text = re.sub(r'["""\'`]', '', text)
    text = re.sub(r'[（）()【】\[\]{}]', ' ', text)
    text = re.sub(r'\s+', ' ', text).strip()
    return text
```

### 4.3 `filename_parser.py` — 파일명 파싱 전처리

파싱 전 파일명 정규화:

```python
def normalize_filename_for_parse(stem: str) -> str:
    """파싱용 파일명 전처리."""
    # NFC 정규화
    stem = unicodedata.normalize('NFC', stem)
    # 전각 구분자 → ASCII 대응
    stem = stem.replace('：', ':').replace('／', '/').replace('　', ' ')
    return stem
```

### 4.4 프론트엔드 — 태그 입력값 경고

태그 편집 저장 시 파일명 변경에 문제가 되는 문자를 감지해 사용자에게 안내:

- TagPanel, BatchTagPanel: 저장 전 `title`, `artist`, `album_title` 필드에 `/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|` 포함 시 노란색 경고 표시
- 경고 문구: `"파일명으로 사용 시 특수문자는 '_'로 대체됩니다"`
- 저장 자체는 허용 (태그 값에는 유효)

### 4.5 자동태그 결과 적용 — 파일명 동기화

자동태그 적용 후 "파일명 변경" 연계 제안 기능(마법사 등):
- 태그에 `?`, `:`, `/` 등이 포함된 경우 파일명 변경 단계에서 자동 sanitize 적용

## 5. 우선순위 및 구현 순서

| 순위 | 작업 | 파일 | 난이도 | 영향 범위 |
|------|------|------|--------|-----------|
| 1 | `sanitize_filename()` 전각 문자 추가 | `pattern_rename.py` | 낮음 | 파일명 변경 전체 |
| 2 | NFC 정규화 추가 | `pattern_rename.py` | 낮음 | macOS 호환성 |
| 3 | 검색 쿼리 정규화 | `metadata/matcher.py` | 중간 | 자동태그 검색 정확도 |
| 4 | 파일명 파싱 전처리 | `filename_parser.py` | 중간 | 파일명 자동태그 |
| 5 | 프론트엔드 경고 표시 | TagPanel, BatchTagPanel | 중간 | UX |

## 7. 참고: 현재 정상 작동 범위

- 한글(가-힣), 일본어(히라가나/카타카나) → 태그/파일명 모두 정상 ✅
- 한자(U+4E00–U+9FFF) → 태그 저장 및 Linux/Mac 파일명 정상 ✅
- 이모지(🎵, ❤️ 등) → 태그 저장은 가능, **파일명 사용 비권장** (일부 OS에서 오류)
- 기본 ASCII 특수문자(`!`, `@`, `#`, `$`, `%`, `&`) → 파일명 허용 ✅
