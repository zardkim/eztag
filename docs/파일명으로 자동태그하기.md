작성일: 2026-04-15

## 1. 개요

### 1.1 기능 요약

현재 자동태그는 **앨범/폴더 단위**로 동작한다.
- 폴더명 파싱 → 앨범 검색 → 트랙 목록 조회 → track_no 매칭 → 일괄 적용

새 기능은 **파일 단위**로 동작한다.
- 파일명 파싱(아티스트 - 제목 등) → 파일별 개별 검색 → 최적 결과 자동 적용

### 1.2 지원 패턴 (예시)

```
아티스트 - 제목.mp3         → %artist% - %title%
아티스트 - 트랙 - 제목.mp3  → %artist% - %track% - %title%
트랙 - 아티스트 - 제목.mp3  → %track% - %artist% - %title%
트랙 - 제목.mp3             → %track% - %title%
```

### 1.3 기존 기능과의 차이

| 항목 | 기존 앨범 단위 | 새 파일 단위 |
|------|-------------|------------|
| 검색 단위 | 폴더/앨범 전체 | 파일 개별 |
| 검색 키워드 | 앨범명 (폴더명 파싱) | 아티스트 + 제목 (파일명 파싱) |
| 트랙 매칭 | track_no 기반 | 제목 + 아티스트 유사도 + 재생시간 |
| 커버 적용 | 앨범 단위 일괄 | 파일 단위 (선택) |
| UI | SpotifySearchDialog (비교 화면) | FilenameAutoTagDialog (진행 + 결과) |
| 적합 상황 | 앨범 단위로 정리된 폴더 | 파일명에 아티스트/제목이 있는 경우 |

## 3. 구현 설계

### 3.1 전체 흐름

```
[사용자] 파일 선택 → 자동태그 메뉴 → "파일명 자동태그" 선택
    ↓
[FilenameAutoTagDialog] 패턴 선택 + 미리보기
    ↓ (프리뷰 API 호출)
[POST /browse/tag-from-name/preview] 파일명 파싱 결과 반환
    ↓
[사용자] 소스 선택 (Spotify/Bugs/Melon/Apple Music) + 실행
    ↓
[POST /metadata/auto-tag-by-filename] 파일별 검색 → 매칭 → 적용
    ↓
[FilenameAutoTagDialog] 진행 표시 → 완료 후 결과 요약
    ↓
[browserStore] 파일 목록 새로고침
```

### 3.2 매칭 점수 알고리즘

각 파일에 대해 검색 결과 후보들을 점수로 평가해 최적 결과를 선택한다.

```python
def _score_match(parsed: dict, candidate: dict, local_duration: float = None) -> float:
    score = 0.0

    # 제목 유사도 (최대 50점)
    title_sim = string_similarity(
        normalize(parsed.get("title", "")),
        normalize(candidate.get("title", ""))
    )
    score += title_sim * 50

    # 아티스트 유사도 (최대 30점, 패턴에 %artist%가 있을 때만)
    if parsed.get("artist"):
        artist_sim = string_similarity(
            normalize(parsed["artist"]),
            normalize(candidate.get("artist", ""))
        )
        score += artist_sim * 30

    # 재생시간 근접도 (최대 20점)
    if local_duration and candidate.get("duration_ms"):
        diff = abs(local_duration - candidate["duration_ms"] / 1000)
        if diff <= 2:
            score += 20
        elif diff <= 5:
            score += 10
        elif diff > 15:
            score -= 15

    return score

# 매칭 기준: 70점 이상이면 자동 적용, 미만이면 no_match
MATCH_THRESHOLD = 70.0
```

`string_similarity`는 Python 표준 `difflib.SequenceMatcher`를 사용한다.

`normalize`는 대소문자 통일, 특수문자·괄호·feat. 제거 등 전처리를 수행한다.

### 3.3 신규 API 엔드포인트

#### `POST /api/metadata/auto-tag-by-filename`

**요청 (Request Body):**

```python
class AutoTagByFilenameRequest(BaseModel):
    paths: List[str]           # 처리할 파일 경로 목록
    pattern: str               # 파일명 패턴 (예: "%artist% - %title%")
    providers: List[str]       # 검색 소스 (spotify/bugs/melon/apple_music)
    apply_cover: bool = False  # 커버아트도 적용할지 여부
    match_threshold: float = 70.0  # 자동 적용 최소 점수
```

**응답 (Response):**

```python
class FileAutoTagResult(BaseModel):
    path: str
    filename: str
    parsed: dict               # 파싱된 필드 (artist, title, track 등)
    status: str                # "applied" | "no_match" | "parse_error" | "error"
    matched_title: Optional[str]   # 매칭된 곡명
    matched_artist: Optional[str]  # 매칭된 아티스트
    matched_provider: Optional[str]  # 사용된 소스
    score: Optional[float]     # 매칭 점수
    error: Optional[str]       # 오류 메시지

class AutoTagByFilenameResponse(BaseModel):
    results: List[FileAutoTagResult]
    summary: dict              # {applied: int, no_match: int, parse_error: int, error: int}
```

**처리 로직 (의사코드):**

```python
async def auto_tag_by_filename(req, db):
    results = []

    for path in req.paths:
        filename = Path(path).stem  # 확장자 제거

        # 1. 파일명 파싱 (기존 함수 재사용)
        parsed = _parse_filename_by_pattern(filename, req.pattern)
        if not parsed or not parsed.get("title"):
            results.append(FileAutoTagResult(path=path, status="parse_error", ...))
            continue

        # 2. 검색 쿼리 구성
        q_parts = []
        if parsed.get("artist"):
            q_parts.append(parsed["artist"])
        q_parts.append(parsed["title"])
        query = " ".join(q_parts)

        # 3. 각 소스에서 검색 (비동기 병렬)
        candidates = []
        for provider in req.providers:
            try:
                res = await search_tracks_by_provider(query, provider, limit=5)
                candidates.extend(res)
            except Exception:
                pass

        if not candidates:
            results.append(FileAutoTagResult(path=path, status="no_match", ...))
            continue

        # 4. 로컬 파일 재생시간 조회 (DB)
        track = db.query(Track).filter(Track.file_path == path).first()
        local_duration = track.duration if track else None

        # 5. 최적 매칭 선택
        best = max(candidates, key=lambda c: _score_match(parsed, c, local_duration))
        best_score = _score_match(parsed, best, local_duration)

        if best_score < req.match_threshold:
            results.append(FileAutoTagResult(path=path, status="no_match", score=best_score, ...))
            continue

        # 6. 태그 적용 (기존 apply_metadata 로직 재사용)
        updates = _build_updates_from_candidate(best, parsed)
        write_tags(path, updates)
        if track:
            for k, v in updates.items():
                setattr(track, k, v)
        db.commit()

        if req.apply_cover and best.get("cover_url"):
            _embed_cover(path, best["cover_url"])

        results.append(FileAutoTagResult(path=path, status="applied", score=best_score, ...))

    summary = Counter(r.status for r in results)
    return AutoTagByFilenameResponse(results=results, summary=dict(summary))
```

## 6. 고려사항 및 주의점

### 6.1 검색 API 부하

파일 수가 많을 경우 (예: 50개 파일) 각 파일당 최대 4개 소스를 검색하면 최대 200회 API 호출이 발생한다.

**대응 방안:**
- 같은 아티스트+제목 조합이면 캐시 적용 (처리 중 메모리 캐시)
- 동시 요청 수를 제한 (`asyncio.Semaphore(3)` 등)
- 파일 선택 개수 경고 (예: 20개 초과 시 "시간이 걸릴 수 있습니다" 안내)

### 6.2 매칭 정확도

파일명 규칙이 일정하지 않으면 파싱 실패 또는 오매칭 위험이 있다.

**대응 방안:**
- 미리보기 단계에서 파싱 결과를 사용자에게 먼저 보여줌
- 매칭 점수 기준값(threshold)을 설정에서 조정 가능하게 노출 (기본 70점)
- 미매칭 파일 목록을 결과에서 별도 표시, 수동 재시도 옵션 제공

### 6.3 커버아트 처리

파일 단위 자동태그에서 커버를 적용하면 파일마다 다른 커버가 임베드될 수 있다.

**대응 방안:**
- 기본값은 커버 적용 OFF
- 커버 적용 시 주의 안내 문구 표시

### 6.4 기존 마법사와의 연동

마법사의 "자동 태그" 단계는 현재 `SpotifySearchDialog`(앨범 단위)를 사용한다.

향후 마법사 설정에 "자동태그 방식" 옵션 추가 가능:
- `album` (기본): 현재 방식, 앨범 단위 검색
- `filename`: 새 방식, 파일명 파싱 후 파일 단위 검색

단, 마법사 연동은 이번 구현 범위에서 제외하고 이후 확장으로 남긴다.

## 8. 향후 확장 가능성

- **백그라운드 처리**: 파일 수가 많을 때 기존 LRC/YouTube 백그라운드 Job 패턴으로 전환 (JobStore 연동)
- **마법사 연동**: 마법사 "자동 태그" 단계에 방식 선택 옵션 추가
- **수동 매칭 UI**: 미매칭 파일에 대해 검색 결과를 직접 선택할 수 있는 UI 추가
- **패턴 자동 감지**: 폴더 내 파일명을 분석해 가장 적합한 패턴 자동 추천
- **매칭 임계값 설정**: Settings 페이지에서 전역 설정 가능하도록 노출
